# Rebrand portal shell to BetterKananga for Kananga, Leyte

Cycle: 20260903-48acf0
Started: 2026-09-03T22:20:00.000Z

## Goal

Rebrand the portal shell from BetterGov.ph to BetterKananga, the community-run website for the Municipality of Kananga, Leyte, and introduce one central site config module that holds the brand and the municipal facts so later cycles localize data instead of hunting scattered strings.

## Approach

Add src/config/site.ts exporting SITE (brand name, domain, tagline, description) and MUNICIPALITY (province, region, income class, 2020 population, barangay count, coordinates, mayor, vice mayor) built from sourced data: PhilAtlas 2020 census, ABS-CBN Halalan 2025 results, Tagalog Wikipedia. Thread it through the SEO component, the SEO title templates, the navbar and footer wordmarks, and the English hero and copyright strings.

Rejected: replacing strings across all 48 files that mention bettergov in one pass, because that diff blows the 400 line gate and scattered strings drift. Rejected: swapping logo assets and all 13 locales now, same size reason; logged as debt for follow-up cycles.

Defaults picked without blocking, revisable: brand name BetterKananga, domain betterkananga.ph, BetterGov logo assets stay this cycle.

This cycle replaces abandoned cycle 20260903-64e743, which had started before the tooling chore commit and counted it in its gates. The work is identical.

src/lib/utils.ts is included because formatDate rendered UTC dates in machine local time and failed the existing unit test on machines behind UTC; the fix pins the format to UTC. package-lock.json changes because npm update patched vulnerable transitive dev tooling packages (tar, fast-uri, sharp, pacote, sigstore and friends) so the audit gate passes. package.json changes one pin: the ws override moves from 8.20.1 to ^8.21.0 because every 8.x up to 8.20.1 carries a high severity advisory. public/llms.txt and public/sitemap.xml are regenerated by the build step generate:metadata. The two .unslopped files are bookkeeping written by the tool itself. The new config module is src/config/site.ts with tests in src/config/__tests__/site.test.ts and src/lib/__tests__/seoTemplates.test.ts.

## Preferences
- PR review comments use plain language: short sentences, no jargon, severity said in human words  (global)
- Every command the tool asks a human to run must arrive with its context: what was verified, what it unlocks, how to decline  (global)
- Never stage .unslopped/DEBT.md in a feature commit or PR; it is an append-only log that conflicts on every parallel branch. Leave it in the working tree and commit it separately  (global)
- Run every unslopped command yourself; never tell the user to type one in the terminal. Mechanical commands (start, next, red, propose, commit) just run. Human-decision commands (approve, reset, rollback) pop the permission prompt on their own in the same turn: show the brief or proposal, then run the command right after so the dialog appears. The user only clicks allow or deny. Never make the user reply first to trigger a prompt.  (global)
- When a design question has a sensible default, pick it and note it as revisable instead of blocking; the user prefers iterating over answering questions up front  (global)
