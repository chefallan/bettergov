# Render SEO head tags natively so production builds get titles

Cycle: 20260904-beac4f
Started: 2026-09-04T14:10:00.000Z

## Goal

Every page gets its title, description and social tags in production builds. react-helmet-async 2.0.5 renders no head tags under React 19 in production (the live bettergov.ph upstream shows the same empty document.title), so the SEO component moves to React 19 native head tag rendering and the library leaves the dependency tree.

## Approach

React 19 hoists title, meta and link elements rendered anywhere in the tree into the document head, so the SEO component keeps its exact tag output and drops the Helmet wrapper: the fragment replaces the keyed Helmet element, and the forceUpdate effect that existed to refresh Helmet on route changes goes away because useLocation already re-renders the component. JSON-LD script tags render in place; search engines read structured data from the body. main.tsx loses the HelmetProvider wrapper, the three test files lose their HelmetProvider imports, and react-helmet-async leaves package.json together with its react override pins. Thirteen pages imported Helmet directly beyond the SEO component; each swaps the Helmet element for a fragment the same way. Removing the library hit the npm peer conflict between wrangler 4.129 and @cloudflare/workers-types 4, so the types package moves to ^5, the pairing wrangler expects.

Rejected: upgrading react-helmet-async, because no released version fixes React 19 production rendering. Rejected: keeping the library alongside native tags, because two head managers fight over the same elements.

Red first: a new test renders SEO with no provider wrapper and expects the DC.language meta in the document head; under Helmet this renders nothing without a provider, natively it passes.
